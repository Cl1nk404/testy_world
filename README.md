# Вкусные истории мира — MVP

Ежедневная генерация рецепта на русском языке через **GigaChat-3-Ultra**, сохранение в SQLite и публикация через выбранный канал: Telegram или браузерный черновик в Дзене с Playwright.

## Модель и тариф

Проект использует `GigaChat-3-Ultra` через GigaChat API с областью доступа `GIGACHAT_API_PERS`. По официальной документации модель доступна физическим лицам в режиме Freemium; фактические квоты и доступность зависят от аккаунта. Бесплатный режим не означает неограниченные запросы. См. [документацию GigaChat 3 Ultra](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra) и [документацию Python SDK](https://developers.sber.ru/docs/ru/gigachain/tools/python/gigachat).

## Важные ограничения MVP

- Сначала запускайте с `DRY_RUN=true`: материал будет создан локально, но не отправлен в Telegram.
- Генерация изображений подключена через Cloudflare Workers AI (FLUX.1 Schnell), но выключена по умолчанию; для работы нужны Account ID и API Token.
- Интеграция с Дзеном через Playwright на текущем этапе только создаёт черновик и не нажимает «Опубликовать».
- Валидатор проверяет базовую структуру, но не гарантирует фактическую безопасность или правильность каждого рецепта. Первые публикации следует проверять вручную.
- Для кросс-постинга настройте синхробота Дзена и укажите публичный Telegram-канал, связанный с вашим каналом Дзена.
- При `DRY_RUN=false` бот должен быть администратором Telegram-канала с правом публикации сообщений.
- Проверка TLS включена по умолчанию. Если среда не доверяет сертификату API, установите корневой сертификат НУЦ Минцифры и настройте доверие в системе; не отключайте TLS-проверку без необходимости.

## 1. Установка

Требуется Python 3.11 или новее.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

## 2. Подключить GigaChat 3 Ultra

1. Откройте [страницу GigaChat API](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra) и перейдите к подключению API для физического лица.
2. Создайте проект/получите ключ авторизации в личном кабинете GigaChat API. Для Freemium Ultra используйте аккаунт физического лица.
3. В `.env` заполните `GIGACHAT_CREDENTIALS` полученным ключом авторизации. Это именно ключ авторизации, а не краткоживущий Bearer-токен.
4. Оставьте `GIGACHAT_MODEL=GigaChat-3-Ultra`, `GIGACHAT_SCOPE=GIGACHAT_API_PERS` и `GIGACHAT_BASE_URL=https://api.giga.chat/v1`.
5. `GIGACHAT_VERIFY_SSL_CERTS=true` оставьте включённым. Если появится ошибка сертификата, установите сертификаты Минцифры по [официальной инструкции](https://developers.sber.ru/docs/ru/gigachat/certificates).

Не публикуйте `.env`, ключ авторизации или токены в чатах и репозитории.

## 3. Настроить Telegram

1. Создайте бота через `@BotFather` и скопируйте токен.
2. Добавьте бота администратором в публичный Telegram-канал с правом публикации сообщений.
3. Укажите токен в `TELEGRAM_BOT_TOKEN`.
4. В `TELEGRAM_CHANNEL` укажите `@username` канала.
5. Убедитесь, что канал уже связан с вашим каналом Дзена через синхробот Дзена.

## 4. Сначала тест без публикации

В `.env` оставьте `DRY_RUN=true`, затем выполните:

```bash
python -m app.main --once
```

Ожидаемый результат: Markdown-файл появится в `output/`, а журнал — в `logs/service.log`. Никакое сообщение в Telegram не отправляется. Для теста необходимы действующий ключ GigaChat и сетевой доступ к API.

## 5. Включить публикацию

После проверки текста установите `DRY_RUN=false` и выполните запуск вручную:

```bash
python -m app.main --once --force
```

Убедитесь, что сообщение появилось в Telegram, а затем проверьте его перенос в Дзен. `--force` повторно запускает обработку за текущую дату, поэтому используйте его осторожно: для реальной публикации это может создать дубликат.

## 6. Ежедневный запуск

```bash
python -m app.main
```

Окно терминала должно оставаться открытым, а компьютер — включённым и не переходить в сон. Для автозапуска после перезагрузки настройте Планировщик заданий Windows или systemd/cron на macOS/Linux. По умолчанию расписание — ежедневно в 09:00 Europe/Moscow.

## 7. Текущие известные ограничения

- Выбор темы пока использует сезонный список-кандидат и список ранее использованных тем.
- Проверка качества базовая и не является экспертной проверкой рецепта.
- Ошибка за день записывается в SQLite; повторный запуск за ту же дату требует `--force`.
- Изображения генерируются через Cloudflare Workers AI при `ENABLE_IMAGE=true` и сохраняются в `output/images`.


## Настройка браузерной интеграции с Дзеном (Windows)

На первом этапе сервис создаёт **черновик** в редакторе Дзена. Автоматическое нажатие «Опубликовать» пока намеренно не включено — сначала нужно проверить редактор на вашем канале.

1. Установите зависимости в активированном виртуальном окружении: `pip install -r requirements.txt` и `playwright install chromium`.
2. Запустите `scripts\start_chrome.bat`. Откроется отдельный профиль Chrome, не использующий основной профиль браузера.
3. В открывшемся окне вручную войдите в аккаунт Яндекса и откройте редактор своего канала Дзена. Если редактор не открывается по адресу из `DZEN_EDITOR_URL`, скопируйте адрес редактора своего канала в эту переменную файла `.env`.
4. В `.env` установите `PUBLISHER=dzen`, `DRY_RUN=false`, `DZEN_CDP_URL=http://127.0.0.1:9222` и `DZEN_EDITOR_URL=https://dzen.ru/profile/editor/create`. Важно: `DRY_RUN=false` разрешает сервису создавать черновик; текущая версия скрипта не нажимает кнопку финальной публикации.
5. Оставьте окно специального Chrome открытым и запустите тест на последней сохранённой статье: `python -m app.dzen_publisher --last-post`. Эта команда не вызывает GigaChat, но создаёт черновик в Дзене. Если тест прошёл, проверьте черновик в редакторе. Для следующего теста удалите предыдущий тестовый черновик вручную, чтобы не плодить дубликаты.
6. Проверьте редактор Дзена: статья должна появиться в виде черновика. Журнал находится в `logs/service.log`; при ошибке скрипт сохраняет диагностический скриншот в `logs/dzen_editor_error.png`.

**Безопасность:** не публикуйте папку профиля `%LOCALAPPDATA%\TastyWorldChrome` и не передавайте её другим людям — в ней хранится авторизованная сессия. Порт CDP слушает только localhost. Если редактор изменит интерфейс, автоматизацию нужно остановить и обновить селекторы. Не обходите CAPTCHA; пройдите проверку вручную в открытом Chrome.

Чтобы вернуться к Telegram, установите `PUBLISHER=telegram`. Для первой проверки Дзена используйте тестовую статью и не запускайте ежедневный планировщик одновременно.
